# 자연어 브리핑 템플릿 커스터마이징 -- 출력 형식 설계

> **Status**: Draft v2
> **Date**: 2026-02-27
> **Author**: UI/UX Design Agent
> **Target version**: v2.1.0 (예정)
> **Applies to**: Claude Code (터미널), OpenClaw (채팅), Cowork (채팅)
> **Supersedes**: 기존 `skills/briefing-customizer/SKILL.md` 및 `commands/customize.md`의 출력 형식 정의를 대체

---

## 설계 원칙

1. **터미널 + 채팅 양립**: 순수 마크다운만 사용. 이모지는 사용하지 않고 ASCII 기호(`>`, `*`, `-`)로 대체
2. **정보 계층화**: 요약 -> 상세 순서. 핵심 정보가 첫 5줄 안에 드러나야 함
3. **일관된 패턴**: 모든 출력이 `[상태 헤더] -> [테이블/목록] -> [후속 안내]` 3단 구조
4. **에러 복구 경로 명시**: 모든 에러 메시지에 구체적인 해결 방법 포함
5. **플랫폼 분기 최소화**: Claude Code 슬래시 커맨드와 자연어 안내를 항상 함께 제공

### 출력 형식 규칙

- 하위 구분은 항상 `###` 헤더 사용 (`**볼드:**` 텍스트 구분 금지)
- 확인/안내 문구는 항상 인용 블록(`>`)으로 묶음
- 후속 안내는 슬래시 커맨드 + 자연어를 병기
- 테이블은 5열 이하, 합산 문자 수 80열 이내

## 1. 설정 조회 출력 형식

### 트리거

- Claude Code: `/smart-briefing:customize` 또는 `/smart-briefing:customize show`
- 자연어: "브리핑 설정 보여줘", "현재 설정"

### 출력 형식

```markdown
## 현재 브리핑 설정

| 항목 | 값 |
|------|-----|
| 프리셋 | default |
| 활성 섹션 | 5/9개 |
| 조회 기간 | 최근 7일 |
| 이상 탐지 임계값 | 20% |
| 최대 인사이트 | 5개 |
| 최대 액션 아이템 | 4개 |

### 활성 섹션 (5/9)

| # | 섹션 | 상태 | 구성 | 제한 |
|---|------|------|------|------|
| 1 | 핵심 지표 오버뷰 | ON | sessions 외 6개 | 이전 기간 비교 |
| 2 | 상위 페이지 | ON | screenPageViews 외 2개 / pagePath | 상위 10개 |
| 3 | 트래픽 소스 | ON | sessions 외 2개 / sessionSource 외 1개 | 상위 10개 |
| 4 | 일별 트렌드 | ON | sessions 외 1개 / date | - |
| 5 | 디바이스별 분석 | ON | sessions 외 2개 / deviceCategory | - |
| 6 | 캠페인 성과 | OFF | sessions 외 2개 / sessionCampaignName 외 1개 | 상위 10개 |
| 7 | 이벤트 분석 | OFF | eventCount 외 1개 / eventName | 상위 10개 |
| 8 | 랜딩 페이지 | OFF | sessions 외 2개 / landingPage | 상위 10개 |
| 9 | 사용자 행동패턴 | OFF | engagementRate 외 4개 | 이전 기간 비교 |

### 커스텀 섹션 (0개)

커스텀 섹션이 없습니다. 추가하려면:
- "전환 분석 섹션 만들어줘"
- "이탈 퍼널 섹션 추가해줘"

### 프리셋

| 구분 | 프리셋명 | 활성 섹션 수 |
|------|---------|-------------|
| 내장 | default (현재) | 5개 |
| 내장 | behavior | 5개 |
| 내장 | traffic | 5개 |
| 내장 | campaign | 5개 |
| 내장 | content | 5개 |

커스텀 프리셋이 없습니다. 현재 설정을 저장하려면:
- "이 설정을 '마케팅팀' 프리셋으로 저장해줘"

---

> 변경하시려면 자연어로 말씀해주세요.
> 예: "캠페인 위주로 바꿔줘", "이벤트 섹션 추가해줘"
> Claude Code: `/smart-briefing:customize preset {이름}`
```

### config.json이 없는 최초 상태

```markdown
## 현재 브리핑 설정

기본 설정을 사용 중입니다. (config.json 파일 미생성)

| 항목 | 값 |
|------|-----|
| 프리셋 | default (기본값) |
| 활성 섹션 | 5/9개 |
...

> 설정을 변경하면 config.json이 자동 생성됩니다.
```

### 설계 의도

- **구성 열**: 메트릭과 디멘션을 `{메트릭} / {디멘션}` 형식으로 합쳐 80열 이내 유지. 디멘션이 없으면 메트릭만 표시
- **축약 규칙**: 메트릭 3개 이상이면 `{첫번째} 외 N개`, 디멘션 2개 이상이면 `{첫번째} 외 N개`
- **커스텀 섹션/프리셋 영역 분리**: 비어있어도 영역을 보여줌으로써 기능의 존재를 자연스럽게 안내 (빈 상태 = 가이드 역할)
- **번호(#)**: 순서가 브리핑 출력 순서와 동일함을 암시
- **활성 섹션 요약**: 상단 설정 테이블에 `활성 섹션: 5/9개`를 포함하여 핵심 정보를 첫 5줄 안에 노출

## 2. 커스텀 섹션 생성

### 트리거

- "전환 분석 섹션 만들어줘"
- "이탈 퍼널 섹션 추가해줘"
- "캠페인 ROI 섹션 새로 만들어줘"

### 확인 요청 형식

```markdown
## 커스텀 섹션 생성

아래 내용으로 커스텀 섹션을 생성합니다.

| 항목 | 값 |
|------|-----|
| 섹션 ID | conversion_analysis |
| 섹션 이름 | 전환 분석 |
| 상태 | ON |
| 차트 유형 | horizontal_bar |

### 메트릭

| 메트릭 | 설명 |
|--------|------|
| conversions | 전환 수 |
| sessionConversionRate | 세션 전환율 |
| totalRevenue | 총 수익 |

### 디멘션

| 디멘션 | 설명 |
|--------|------|
| sessionSource | 세션 소스 |
| sessionMedium | 세션 매체 |

### 옵션

| 항목 | 값 |
|------|-----|
| 상위 제한 | 10개 |
| 이전 기간 비교 | 사용 |

> 이대로 생성할까요? 메트릭이나 디멘션을 수정하고 싶으면 말씀해주세요.
> 예: "수익 대신 거래 수로 바꿔줘", "제한을 5개로 줄여줘"
```

### 생성 완료 형식

```markdown
## 커스텀 섹션 생성 완료

'전환 분석' 섹션이 생성되었습니다.

| 항목 | 이전 | 변경 후 |
|------|------|---------|
| 활성 섹션 | 5개 | 6개 (+1) |
| 커스텀 섹션 | 0개 | 1개 (+1) |

### 활성 섹션 목록

1. 핵심 지표 오버뷰
2. 상위 페이지
3. 트래픽 소스
4. 일별 트렌드
5. 디바이스별 분석
6. **전환 분석** (신규)

> 다음 브리핑에 반영됩니다. 지금 바로 생성하시겠어요?
> - Claude Code: `/smart-briefing:briefing`
> - 자연어: "브리핑 생성해줘"
```

### 설계 의도

- **2단계 확인 플로우**: 에이전트가 자연어를 해석한 결과를 먼저 보여주고 승인을 받음. 잘못된 해석을 사전에 수정 가능
- **메트릭/디멘션 테이블에 설명 포함**: GA4 API 이름만으로는 이해하기 어려운 사용자를 위해 한국어 설명 병기
- **차트 유형 표시**: 커스텀 섹션의 차트 생성 방식을 사전에 확인 가능 (섹션 7 차트 생성 전략 참조)
- **형식 검증 시점**: 확인 요청 단계에서 메트릭/디멘션 화이트리스트 및 호환성 검증 수행. 유효하지 않으면 에러 6-1/6-2/6-3 반환
- **생성 완료 시 before/after**: 기존 패턴(설정 변경 시 비교 테이블)과 일관성 유지

## 2-2. 커스텀 섹션 수정

### 트리거

- "전환 분석 섹션에서 수익 대신 거래 수로 바꿔줘"
- "전환 분석 섹션에 참여율 추가해줘"
- "전환 분석 섹션 이름을 'CVR 분석'으로 바꿔줘"

### 수정 확인 형식

```markdown
## 커스텀 섹션 수정

'전환 분석' 섹션을 수정합니다.

### 변경 내역

| 항목 | 이전 | 변경 후 |
|------|------|---------|
| 메트릭 | conversions, sessionConversionRate, totalRevenue | conversions, sessionConversionRate, **ecommercePurchases** |

변경 요약: totalRevenue -> ecommercePurchases (1개 교체)

> 이대로 수정할까요?
> 예: "아니, 둘 다 넣어줘", "취소"
```

### 수정 완료 형식

```markdown
## 커스텀 섹션 수정 완료

'전환 분석' 섹션이 수정되었습니다.

| 항목 | 이전 | 변경 후 |
|------|------|---------|
| 메트릭 | totalRevenue | ecommercePurchases |

> 다음 브리핑에 반영됩니다.
```

### 설계 의도

- **diff 중심 표시**: 변경된 항목만 before/after로 표시하여 변경 범위를 명확히 전달
- **변경 요약 1줄**: "N개 추가", "N개 교체" 등 한 줄 요약으로 빠른 확인

## 2-3. 커스텀 섹션 삭제

### 트리거

- "전환 분석 섹션 삭제해줘"
- "전환 분석 커스텀 섹션 제거해줘"

### 삭제 확인 형식

```markdown
## 커스텀 섹션 삭제

'전환 분석' 섹션을 삭제합니다.

| 항목 | 값 |
|------|-----|
| 섹션 ID | conversion_analysis |
| 메트릭 | conversions, sessionConversionRate, ecommercePurchases |
| 디멘션 | sessionSource, sessionMedium |

### 영향

이 섹션을 참조하는 프리셋 1개가 자동 업데이트됩니다:
- '마케팅팀' 프리셋: conversion_analysis 참조 제거

> 삭제하시겠습니까? 이 작업은 되돌릴 수 없습니다.
```

### 프리셋 참조가 없는 경우

```markdown
## 커스텀 섹션 삭제

'전환 분석' 섹션을 삭제합니다.

| 항목 | 값 |
|------|-----|
| 섹션 ID | conversion_analysis |
| 메트릭 | conversions, sessionConversionRate, ecommercePurchases |
| 디멘션 | sessionSource, sessionMedium |

> 삭제하시겠습니까? 이 작업은 되돌릴 수 없습니다.
```

### 삭제 완료 형식

```markdown
## 커스텀 섹션 삭제 완료

'전환 분석' 섹션이 삭제되었습니다.

| 항목 | 이전 | 변경 후 |
|------|------|---------|
| 활성 섹션 | 6개 | 5개 (-1) |
| 커스텀 섹션 | 1개 | 0개 (-1) |

> 프리셋 '마케팅팀'에서 해당 참조가 제거되었습니다.
```

### 설계 의도

- **삭제 전 요약**: 삭제 대상의 구성을 한눈에 보여줘 실수 방지
- **프리셋 참조 연쇄 처리**: 삭제 시 관련 프리셋의 `custom_sections_included`에서 자동 제거. 사용자에게 영향 범위를 사전에 고지
- **되돌릴 수 없음 명시**: 삭제의 비가역성을 안내

## 3. 프리셋 저장

### 트리거

- "이 설정을 '마케팅팀' 프리셋으로 저장해줘"
- "현재 설정을 프리셋으로 저장해줘" (이름 미지정 시 물어봄)
- "지금 설정 저장해줘"

### 이름 미지정 시

```markdown
> 프리셋 이름을 정해주세요.
> 예: "마케팅팀", "주간리뷰", "캠페인분석"
```

### 저장 확인 형식

```markdown
## 커스텀 프리셋 저장

현재 설정을 커스텀 프리셋으로 저장합니다.

| 항목 | 값 |
|------|-----|
| 프리셋 이름 | 마케팅팀 |
| 기반 프리셋 | campaign (수정됨) |
| 활성 섹션 | 6개 |
| 커스텀 섹션 | 1개 포함 |

### 포함 섹션

1. 핵심 지표 오버뷰
2. 캠페인 성과
3. 트래픽 소스
4. 랜딩 페이지
5. 일별 트렌드
6. 전환 분석 (커스텀)

### 저장되는 설정값

| 항목 | 값 |
|------|-----|
| 조회 기간 | 최근 7일 |
| 이상 탐지 임계값 | 25% |
| 최대 인사이트 | 5개 |
| 최대 액션 아이템 | 4개 |

> 이 이름으로 저장할까요?
```

### 저장 완료 형식

```markdown
## 프리셋 저장 완료

'마케팅팀' 프리셋이 저장되었습니다.

| 항목 | 이전 | 변경 후 |
|------|------|---------|
| 커스텀 프리셋 | 0개 | 1개 (+1) |

### 사용 방법

> 불러오기:
> - Claude Code: `/smart-briefing:customize preset 마케팅팀`
> - 자연어: "마케팅팀 프리셋으로 바꿔줘"
>
> 관리:
> - 수정: 설정 변경 후 "마케팅팀 프리셋 업데이트해줘"
> - 삭제: "마케팅팀 프리셋 삭제해줘"
> - 목록: "프리셋 목록 보여줘"
```

### 설계 의도

- **기반 프리셋 표시**: "campaign에서 수정됨"처럼 어떤 프리셋에서 파생되었는지 표시하여 맥락 제공. `base_preset`은 표시용이며, 복원 시에는 `sections_enabled`를 절대 목록으로 사용
- **포함 섹션 + 설정값 분리**: 섹션 구성과 파라미터를 구분하여 프리셋이 "무엇을 보여줄지"와 "어떻게 보여줄지"를 각각 확인 가능
- **저장 완료에 before/after**: 다른 완료 메시지와 일관성 유지
- **저장 완료 후 사용법 안내**: 불러오기/수정/삭제 방법을 모두 안내

```markdown
| 상위 페이지 | ON | OFF |
| 디바이스별 분석 | ON | OFF |
| 캠페인 성과 | OFF | ON |
| 랜딩 페이지 | OFF | ON |
| 전환 분석 (커스텀) | OFF | ON |

> 다음 브리핑에 반영됩니다.
> - Claude Code: `/smart-briefing:briefing`
> - 자연어: "브리핑 생성해줘"
```

### 프리셋 적용 후 개별 섹션 토글 시

프리셋 적용 후 사용자가 개별 섹션을 토글하면 `preset` 필드가 `"{프리셋명} (수정됨)"`으로 변경됩니다.

```markdown
## 섹션 변경 완료

'이벤트 분석' 섹션이 활성화되었습니다.

| 항목 | 이전 | 변경 후 |
|------|------|---------|
| 프리셋 | 마케팅팀 | 마케팅팀 (수정됨) |
| 활성 섹션 | 6개 | 7개 |

> 현재 설정을 새 프리셋으로 저장하려면:
> "이 설정을 '마케팅팀v2' 프리셋으로 저장해줘"
```

### 설계 의도

- **before/after 비교**: 프리셋 간 차이를 명확히 보여주어 변경 범위 인지
- **활성 섹션 변경 테이블**: 전체 목록이 아닌 변경된 섹션만 표시하여 정보량 최소화
- **수정됨 상태 추적**: 프리셋에서 벗어난 상태를 명시하여 사용자가 현재 설정의 출처를 인지

### 카테고리별 축약 조회

사용자가 특정 카테고리만 물어보는 경우:

```markdown
## 전환/수익 관련 메트릭

| 메트릭 | 설명 | 사용 중인 섹션 |
|--------|------|---------------|
| conversions | 전환 수 | - |
| sessionConversionRate | 세션 전환율 | - |
| totalRevenue | 총 수익 | - |
| ecommercePurchases | 전자상거래 구매 수 | - |
| purchaseRevenue | 구매 수익 | - |

> 현재 브리핑에 전환/수익 메트릭이 포함된 섹션이 없습니다.
> 추가하려면: "오버뷰에 전환율 추가해줘" 또는 "전환 분석 섹션 만들어줘"
```

### 설계 의도

- **상태 헤더 추가**: 3단 구조 준수를 위해 "현재 사용 중인 메트릭: N개" 상태 정보를 상단에 배치
- **카테고리 분류**: GA4에는 수십 개의 메트릭/디멘션이 있으므로 카테고리별로 나눠 탐색 부담 감소
- **예시 표현 열**: 사용자가 자연어로 어떻게 말하면 되는지 구체적으로 안내. 이것이 이 가이드의 핵심 가치
- **부정확한 매핑 제거**: sessionsPerUser에서 "재방문율" 제거(별도 지표), advertiserAdCost에서 "CPC" 제거(클릭당 비용은 다른 개념)
- **사용 중인 섹션 표시**: 축약 조회 시 해당 메트릭이 이미 어디서 쓰이고 있는지 표시하여 중복 방지
- **2단계 검증 명시**: 형식 검증(생성 시) + 데이터 존재 검증(브리핑 시)을 구분

```
[어떻게 해결하는지] -- 구체적 행동 안내
```

### 6-5. 프리셋 이름 중복

## 7. config.json 확장 스키마

위 기능들을 지원하기 위한 config.json 확장 구조입니다.

### 7-1. 스키마

```jsonc
{
  "version": "2.1",
  "preset": "default",                // 내장 프리셋명 또는 커스텀 프리셋명. 수정 시 "프리셋명 (수정됨)"
  "briefing": {
    "sections": [
      // ... 기존 내장 섹션 9개 (id, name, enabled, metrics, dimensions, limit, compare_previous)
    ],
    "custom_sections": [
      {
        "id": "conversion_analysis",   // 영소문자 + 숫자 + 언더스코어, 3~30자
        "name": "전환 분석",
        "enabled": true,
        "metrics": ["conversions", "sessionConversionRate", "totalRevenue"],
        "dimensions": ["sessionSource", "sessionMedium"],
        "limit": 10,
        "compare_previous": true,
        "chart_type": "horizontal_bar", // horizontal_bar | line | pie | change_bar | none
        "created_at": "2026-02-25T09:00:00+09:00"
      }
    ],
    "date_range": "7daysAgo",
    "anomaly_threshold": 20,
    "max_insights": 5,
    "max_actions": 4
  },
  "presets": {
    "custom": {
      "마케팅팀": {                     // 1~20자, 한국어/영문/숫자/하이픈
        "base_preset": "campaign",     // 표시용. 어떤 프리셋에서 파생되었는지 안내
        "sections_enabled": ["overview", "campaigns", "traffic_sources", "landing_pages", "daily_trend"],
        "custom_sections_included": ["conversion_analysis"],
        "overrides": {
          "anomaly_threshold": 25
        },
        "created_at": "2026-02-25T09:00:00+09:00"
      }
    }
  },
  // ... 기존 weekly, export, notifications
}
```

### 7-2. 스키마 설계 원칙

- **기존 구조 비파괴**: `sections` 배열은 그대로 유지. `custom_sections`를 별도 배열로 추가
- **프리셋 데이터 경량화**: 커스텀 프리셋은 전체 config 복사가 아닌, `sections_enabled`(절대 목록) + `overrides`만 저장
- **`base_preset`은 표시용**: 복원 시에는 `sections_enabled`를 사용. `base_preset`은 UI에서 "(campaign에서 수정됨)" 표시에만 활용
- **생성일 추적**: 커스텀 섹션과 프리셋에 `created_at` 포함
- **커스텀 섹션 제한**: `custom_sections` 최대 5개
- **커스텀 프리셋 제한**: `presets.custom` 최대 10개
- **`custom_preset_base` 제거**: v2.0 초안에 있었으나, `preset` 필드와 중복이므로 제거. `preset` 필드가 직접 커스텀 프리셋명을 저장

### 7-3. 브리핑 파이프라인 통합

**섹션 순회 순서:**
브리핑 생성 시 `sections` 배열과 `custom_sections` 배열을 순서대로 연결(concatenate)하여 순회합니다. `enabled: true`인 섹션만 처리합니다.

**차트 생성 전략:**
- 내장 섹션: 기존 `SECTION_HANDLERS` 매핑 사용
- 커스텀 섹션: `chart_type` 필드에 따라 범용 핸들러 매핑
  - `horizontal_bar`: 가로 막대 차트 (dimensions이 있는 Top N 데이터)
  - `line`: 라인 차트 (date 디멘션이 포함된 시계열)
  - `pie`: 파이/도넛 차트 (비율 분포)
  - `change_bar`: 변화율 막대 (compare_previous가 true인 집계 데이터)
  - `none`: 차트 없이 텍스트/테이블만 출력
- `chart_type` 미지정 시 자동 추론:
  - `dimensions`에 `date`가 포함 → `line`
  - `dimensions`이 있고 `limit` > 0 → `horizontal_bar`
  - `dimensions`이 비어있고 `compare_previous: true` → `change_bar`
  - 그 외 → `none`

**사이드카 통합:**
- 커스텀 섹션의 메트릭은 사이드카 `metrics` 딕셔너리에 포함
- `comparable_keys`에 자동 추가
- 주간 집계 시 메트릭 분류: `sidecar_schema.py`의 `SUM_METRICS`/`RATE_METRICS`에 이미 포함된 메트릭은 해당 규칙 적용. 미분류 메트릭은 SUM으로 폴백

### 7-4. 프리셋 적용 동작 상세

**프리셋 적용 시:**
1. `sections` 배열의 `enabled` 값을 `sections_enabled` 목록에 따라 변경
2. `custom_sections` 배열에서 `custom_sections_included`에 포함된 섹션만 `enabled: true`, 나머지는 `enabled: false` (섹션 자체는 삭제하지 않음)
3. `overrides`의 값을 `briefing` 하위에 적용
4. `preset` 필드를 프리셋명으로 변경

**`custom_sections_included`에 존재하지 않는 섹션이 있을 때:**
삭제된 커스텀 섹션의 ID는 무시합니다. 에러를 발생시키지 않습니다.

### 7-5. 마이그레이션 (v2.0 → v2.1)

v2.0 config.json을 읽을 때 자동으로 v2.1로 마이그레이션합니다:

| 필드 | v2.0에 없을 때 | 기본값 |
|------|--------------|--------|
| `briefing.custom_sections` | 부재 | `[]` (빈 배열) |
| `presets` | 부재 | `{ "custom": {} }` |
| `version` | `"2.0"` | `"2.1"`로 자동 업데이트 |

- 마이그레이션은 config.json 수정 시 투명하게 처리 (별도 에러/안내 없음)
- 기존 필드(`custom_preset_base`)가 있으면 무시하고 제거

### 7-6. config.json 백업

config.json 수정 전 자동으로 `config.json.bak`에 이전 버전을 백업합니다. 최신 1개만 유지합니다.

## 8. 입력 검증 규칙

### 터미널 가로폭 대응

80열 터미널에서 테이블이 깨지지 않도록:
- 테이블은 5열 이하, 합산 너비 80자 이내
- 메트릭: 3개 이상일 때 `{첫번째} 외 N개`로 축약
- 디멘션: 2개 이상일 때 `{첫번째} 외 N개`로 축약
- 메트릭 + 디멘션을 `구성` 열로 합쳐 표시: `{메트릭} / {디멘션}`
- 내장 프리셋 목록은 ID 나열 대신 설명 + 개수로 표시
